# M4 科研、外交与探索

> 状态：已实现（v0.4.0，2026-11-21）。本文最初是 M4 的实施依据；落地后保留全部设计决策，
> 并在第 9 节记录实现落点与验收结果。

## 1. 目标

M4 把 M0–M3 的“可运行世界”推进为“有长期因果链的远征”：

- 船员与居民的技能真实影响生产、航行、科研、交易、医疗与探索；
- 舰船有类型、货舱、船员铺位与船体状态，船员可以随船移动；
- 未知星域需要探索，勘察与勘探产生可消耗的科研数据与发现；
- 科技树真实修改航线、配方、舰船与市场参数；
- 势力有可交互的关系、税率、委托与冲突，结果进入编年史；
- D0–D4 阶段目标与双终局可判定、可测试、可重放。

验收主轴仍是设计稿中的那条链：**科研解锁高效曲率线圈 → 航线变短 → 边远矿点可运营 → 矿物供给增加 → 价格回落**。

## 2. 总原则

1. 继续使用五个统一抽象与十二阶段 Tick，不新增并行模拟器、不新增 Tick 阶段。
2. 所有持久改变进入 `WorldState`，并进入 `StateHasher`；随机只来自 `RngStreams` 的既有子系统流。
3. 经济仍走 `ResourceLedger` / `MoneyLedger`；任何冲突、委托、税收都不得产生负库存或凭空资金。
4. 配置是内容来源：技能、船型、事件、科技、知识、税率、委托参数均可由世界文件覆盖；核心代码只实现规则。
5. 不为旧配置写兼容层。默认世界、XSD、测试与文档在同一批次同步升级。
6. 事件不是第二套执行引擎。事件是**不可变事实**；跨系统后果由阶段 10 内固定顺序的反应链调用领域服务完成，不引入异步状态写入。

## 3. 已确定的设计决策

### 3.1 技能：`SkillSet`

每个 `Agent` 拥有六项技能，取值 0–10：

| 技能 | 作用 |
|---|---|
| 驾驶 `PILOT` | 降低航程事故概率 |
| 工程 `ENGINEERING` | 提高生产、维修工作速度 |
| 科研 `RESEARCH` | 推进科研项目 |
| 医疗 `MEDICAL` | 降低物资短缺造成的士气损失 |
| 贸易 `TRADE` | 缩小买卖价差 |
| 探索 `EXPLORATION` | 加快勘察、提高发现质量 |

统一工作系数：

```text
有效工作 = 0.75 + 0.05 × 相关技能
```

技能 5 为基准 1.0，0 为 0.75，10 为 1.25。`WorkUnit` 的进度改为 `BigDecimal`，避免工作速度引入浮点误差。技能成长：同一主体连续从事相关工作每满 30 天，用 `AGENTS` 流判定一次，10% 概率提升对应技能 1 点，上限 10。

配置改为显式的六项技能：

```xml
<agent id="1" name="林舟" role="CREW" at="ship:1" trait="DILIGENT">
  <skills pilot="7" engineering="4" research="2" medical="1" trade="3" exploration="5"/>
</agent>
```

不再保留单一 `skill` 属性。

### 3.2 舰船：类型、容量、船员与船体

- 新增 `ShipType` 配置表，默认五种：勘探、货运、工程、科研、护卫。
- 每型定义 `cargoCapacity`、`crewCapacity`、`maxHull`、`baseRiskFactor`。
- 舰船货舱容量包含燃料与全部货物；交易、装载和初始配置都不得超过容量。
- 船员通过 `at="ship:<id>"` 配置在舰上；`Ship` 仍是 `Location`，船员、库存与事件使用同一位置空间。默认世界必须为 3 艘初始舰船配置船员，并校验铺位容量。
- 船员可以在同一地点的舰船与设施之间调动；调动受 `crewCapacity` 限制。
- 舰船新增 `hull`。船体为 0 时不能启航、交易或执行勘察，但不会永久损失；可在具备维修能力的停泊地点修复。
- 勘探舰是勘察任务的主要载体；科研舰提供移动实验室容量，M4 默认世界不新增舰船。

### 3.3 设施与岗位

- `Facility` 是静态 `Location`，属于某个 `Colony`；新增 `facilityKind`（农场/工坊/精炼厂/实验室/仓库/船坞）与 `workerCapacity`。
- 配方可以挂在地点或设施上；设施上的配方只能使用该设施的工人，工人数受 `workerCapacity` 限制。
- 玩家殖民地的实验室能力由殖民等级提供：等级 1/2/3 分别提供 1/2/3 个科研岗位。M4 不新增设施建造命令；这是殖民地升级的内在能力，不是临时占位。
- NPC 实验室与船坞使用 `Facility` 节点；船坞设施提供造船订单能力。

### 3.4 航程风险

出航时计算一次航程风险：

```text
routeRisk = min(0.90, Σ link.risk + 风暴风险修正)
pilotBonus = 船上最高 PILOT × 0.01
incidentChance = clamp(routeRisk - pilotBonus, 0, 0.90)
```

用 `EVENTS` 流判定一次；事故结果按第二次抽样落在三类之一：

- 延误：航程增加 1–2 天；
- 货损：随机一种货舱货物损失 5%–15%（不超过现有数量）；
- 船体损伤：5–20 点。

事故写入编年史并立即产生 `VoyageIncident`。不出现“无中生有”的损失，不允许负库存，M4 不做舰船永久损毁。

### 3.5 事件与反应顺序

- 事件配置进入世界文件：基础概率、天气系数、强度范围、传播上限、价格冲击、援助代价。
- 事件记录仍是不可变 sealed 类型，全部定义在 `fc-world`。
- 产生事件的主系统立即写入主后果；阶段 10 在事件生成后执行固定顺序的跨系统反应：
  1. 工程/舰船反应；
  2. 势力反应；
  3. 市场反应；
  4. 目标/终局反应。
- 反应可以产生后续事件，但最多两轮；每轮按系统 id 与事件 id 排序。阶段 10 结束前必须收敛，否则视为实现错误。
- `Flow` 仍只在 tick 结束后广播，不参与状态写入。
- 事件配置示例：

```xml
<events>
  <event type="ION_STORM" baseChance="0.02" weatherFactor="0.05"
         minSeverity="1" maxSeverity="4" maxImpacts="8" maxDepth="3"
         shockPercentPerSeverity="0.05" shockDays="3"
         aidCostPerSeverity="200"/>
  <event type="PIRACY" baseChance="0.0" riskFactor="0.5" reputationBelow="0"/>
</events>
```

字段必须经过 XSD 与语义校验：概率在 0..1、强度上下界有序、持续天数与传播上限为正。

### 3.6 定价、税与精度

- 价格链全部使用 `BigDecimal`。弹性以两位小数配置，转为精确有理数后计算：先做整数幂，再用牛顿迭代求根，最终价格保留 2 位。
- 势力控制的地点按势力税率征税：
  - 地点归属势力，或地点是该势力中心，即为受控地点；
  - 买入总额 = 基准买价 × `(1 + 税率)`，卖出到账 = 基准卖价 × `(1 − 税率)`；
  - 税额 = 含税毛额 × 税率，转入势力账户；玩家地点与中立地点税率为 0；
  - 贸易协定使该势力控制地点的税率减半。
- 税率与价格显示在 `market` 面板；交易与税额分别记账，资金总量守恒。
- 家庭部门的消费回流不在 M4 内实现，工资仍是运营成本；该问题留到 M5 的生活经济设计。
- 贷款命令在 M4.0 补齐：`borrow <金额>` 把银行资金转入玩家账户并形成债务，单笔与未偿总额都不得超过银行当前余额；`repay <金额>` 从玩家账户偿还，金额不得超过债务或玩家余额。利息仍按未偿本金逐日计提并转入银行，所有路径都不得透支。

### 3.7 阶段目标与贸易线

“知名”统一定义为对某势力声望 ≥ 20。D0–D4 判定如下：

| 阶段 | 达成条件 |
|---|---|
| D0 生存 | 第 10 天起，玩家控制地点、玩家舰船货舱与在途运输中的食物总量与燃料总量各自都不低于 10 天前的值；至少一条补给线完成过发运 |
| D1 立足 | 玩家殖民地等级 ≥ 1；与任意势力签订贸易协定；该势力声望 ≥ 20 |
| D2 扩张 | 舰队 ≥ 5 艘；已知地点 ≥ 12；完成一项 Tier 2 科技 |
| D3 自主 | 按当前配方与自然产出计算的玩家殖民地食物/水日产能 ≥ 日消费；与至少一个势力结盟 |
| D4 终局 | 完成星门或信标工程之一 |

“贸易线”从此只指**贸易协定**；补给线是物流设施，不再被当作贸易线。玩家初始有 1 个殖民地、世界另有 2 个 NPC 殖民地；“1 个殖民地”指玩家侧规模。

### 3.8 知识状态与探索

每个地点有四种知识状态：

| 状态 | 可见内容 | 能否抵达 |
|---|---|---|
| `UNKNOWN` | 不可见 | 否 |
| `DETECTED` | 未知信号、相邻位置 | 可从已知端点盲航 |
| `SURVEYED` | 名称、类型、航线、市场 | 是 |
| `CHARTED` | 全部内容、发现物、隐藏航线 | 是 |

- 默认世界起始 6 个地点为 `SURVEYED`；与其相邻的未知地点为 `DETECTED`，其余为 `UNKNOWN`。
- 舰船抵达 `DETECTED` 地点后自动转为 `SURVEYED`。
- 在 `SURVEYED` 地点停泊时可以执行勘察；勘察需要时间，舰船在期间锁定：
  - 工期 = `max(2, 6 - floor(EXPLORATION / 2))` 天；
  - 完成地点转 `CHARTED`，揭示隐藏航线与发现物；
  - 产出 `1 + floor(EXPLORATION / 4)` 单位科研数据到舰船货舱；
  - 有 `10% + EXPLORATION × 3%` 概率产生遗迹/矿脉/异常类发现，使用 `EVENTS` 流判定。
- 发现物是持久状态并进入编年史；M4 不生成新地点，16 个地点全部来自配置。惰性生成留到扩大世界规模时处理。

### 3.9 科研与技术效果

- 科技树按 Tier 1–3 配置，节点包含研究成本、科研数据成本、前置科技与效果。
- 科研项目是 `WorkUnit`，键为 `research:<tech>`；每个科研岗位提供 1 个工人位。
- 开始项目消耗配置的科研数据；此后每 tick 由被指派为 `RESEARCH` 的主体按科研技能推进；没有工人、没有岗位或没有前置科技时进度为 0。
- 科技效果是持久修饰器，按类别求和后统一应用：
  - 航线天数百分比；
  - 配方产出百分比；
  - 舰船货舱容量；
  - 工作速度；
  - 税率百分比；
  - 勘察速度。
- 航线天数最低为 1；所有效果进入 `StateHasher`。
- 默认科技树：

| Tier | 科技 | 效果 | 前置 |
|---|---|---|---|
| 1 | 测绘无人机 | 勘察工期 −25% | 无 |
| 1 | 水培农业 | 农场配方产出 +25% | 无 |
| 1 | 货舱框架 | 舰船货舱 +50 | 无 |
| 2 | 高效曲率线圈 | 航线天数 −20%（最低 1 天） | 任一 Tier 1 |
| 2 | 自动化工坊 | 生产工作速度 +15% | 任一 Tier 1 |
| 2 | 贸易协议标准 | 势力税率 −50% | 任一 Tier 1 |
| 3 | 星门理论 | 解锁星门工程 | 任一 2 项 Tier 2 |
| 3 | 信标理论 | 解锁信标工程 | 任一 2 项 Tier 2 |
| 3 | 自持农业 | 殖民地食物/水消费 −20% | 任一 2 项 Tier 2 |

- Tier 2 的“高效曲率线圈”提供航线天数 −20%，是 M4 的主验收链。

### 3.10 外交与委托

声望分级：敌对 ≤ −40，戒备 −39..−1，中立 0..19，知名 20..49，信任 50..79，同盟 80+。

玩家外交动作需要一艘玩家舰船停泊在该势力中心：

- `gift <势力> <信用点>`：资金转入势力账户，每 100 信用点提升 1 点声望，至少 1 点、单次最多 +5；
- `treaty <势力> trade`：声望 ≥ 20、支付 200 信用点，签订贸易协定；
- `treaty <势力> nonaggression`：声望 ≥ 50、支付 500 信用点；
- `treaty <势力> alliance`：声望 ≥ 80、支付 1000 信用点，且已完成过该势力的一次委托；
- `threaten <势力>`：立即进入冲突结算，声望下降。

势力在阶段 3 生成委托：优先货物短缺时发布采购委托，包含货物、数量、交付地点、截止日、报酬与声望奖励。玩家用 `commission accept` 接单，把货物留在舰上运到交付地点，用 `commission deliver` 交付；到期未交付则声望下降。委托消耗舰船货物与势力资金，双方账本守恒。

### 3.11 冲突

冲突是事件化结算，不做战术棋盘。

```text
fleetPower = Σ max(1, floor(hull / 20)) + 最高 PILOT + 最高 ENGINEERING
             + 10 × 介入的同盟数
threatPower = 势力基础军力 + floor(reserve / 200) + floor(max(0, -声望) / 10) + 5
score = fleetPower - threatPower + rng(-5..5)
```

势力基础军力按类型：军事 20、贸易 12、殖民 10、科研 8。用 `EVENTS` 流取一次 `-5..5`；`score ≥ 10` 为威慑，`0..9` 为交火，`< 0` 为赎金。结果只允许：

- 威慑：声望下降，无物资损失；
- 交火：船体损伤 10–30，随机货物损失 10%–25%；
- 赎金：支付信用点，声望小幅回升；
- 有同盟且 `score < 0` 时，损失减半并记录援助事件。

所有损失只能从现有库存扣除；冲突结果写入 `ConflictEvent`。`threaten` 与低声望下的海盗事件（概率由事件配置）都使用同一结算器。M4 不实现舰船沉没与人员死亡。

### 3.12 目标、舰队扩张与终局

- `goals` 面板展示 D0–D4、当前已知地点、舰队、协定、科技与工程进度。
- 船坞设施提供 `order ship <类型> <名称>`：扣除信用点、材料与设备，生成 `ShipyardOrder`；工期内由船坞工人推进，完成后在船坞生成新舰船。新舰船没有自动船员，必须由玩家从同地点的船员中调配。
- D4 两项工程：
  - 星门：在猎户之门（异常点）启动，要求 `gate-theory`、科研数据与设备；
  - 信标：在玩家 3 级殖民地启动，要求 `beacon-theory`、材料与设备。
- 启动一项工程后另一项锁定；工程完成触发 `EndingReached`，记录终局与编年史封卷。终局后仍可查询，但不再推进时间。

## 4. 分步实施

### M4.0 统一模型补齐

交付：

1. `SkillSet` 数据模型、配置装载与默认世界迁移；
2. 船型表、货舱容量、船员铺位、船员随船配置与船体状态；
3. 船员在舰船/设施之间调动的命令与容量校验；
4. `BigDecimal` 工作进度与技能系数；
5. 航程风险结算；
6. 事件参数配置化与阶段 10 固定反应链；
7. 地点控制关系与税率数据；`BigDecimal` 精确幂运算；
8. 贷款 `borrow` / `repay` 命令。

验收：配置可加载、账本守恒、风险可重放、技能影响可观察、价格精度测试通过；不删除或弱化既有测试。

### M4.1 迷雾与探索

交付：

1. 知识状态、配置初始已知地点、地图过滤；
2. `scan`、`survey`、`survey cancel` 与舰船锁定；
3. 到达揭示、勘察揭示、发现物与科研数据；
4. `DiscoveryEvent`、知识状态进入哈希；
5. 探索技能影响工期与产出。

验收：初始地图只显示 6 个已知地点及相邻信号；航行到未知点后可见；勘察后完整揭示；发现物可查询、可重放、不可回滚。

### M4.2 科研与技术效果

交付：

1. 科技树配置与 `fc-science` 实现；
2. 实验室岗位、科研指派、科研项目与科研数据消耗；
3. `TechEffect` 对航线、配方、货舱、工作速度、税率、勘察的作用；
4. `research` 面板、`research start`、`assign ... research`；
5. “高效曲率线圈”因果链集成测试。

验收：同一种子下，完成科技前后的航线天数、矿物供给与价格变化可复现；科技效果进入哈希。

### M4.3 外交、委托与冲突

交付：

1. 声望分级、贸易协定与税率减半；
2. `gift`、`treaty`、`commission list/accept/deliver`、`threaten`；
3. 势力委托生成、到期失败与报酬结算；
4. 冲突结算、船体损伤、修复命令与海盗事件；
5. 势力间关系的确定性漂移。

验收：委托与冲突全程货物/资金守恒；低声望航线冲突可重放；贸易协定改变税率但不改变基础报价。

### M4.4 目标与终局

交付：

1. D0–D4 目标追踪与阶段事件；
2. 船坞订单、舰队扩容；
3. 星门/信标工程与双终局；
4. 终局后状态锁定与最终报告；
5. README、M4 规格、架构与测试文档同步。

验收：固定种子 + 操作脚本可从 D0 走到至少一个终局；终局状态稳定；所有目标判定有测试。

## 5. Tick 与命令落点

| 阶段 | M4 新增职责 |
|---|---|
| 1 时间 | 清理到期修正；目标判定所需日快照 |
| 2 环境 | 自然产出；殖民地维护；设施容量约束 |
| 3 势力 | 采购、委托生成、势力关系漂移 |

## 6. 模块边界

| 模块 | M4 职责 |
|---|---|
| `fc-world` | `SkillSet`、知识、船型/容量/船体、发现、科技状态、协定、委托、冲突记录、目标状态 |

| `fc-diplomacy` | 外交动作、委托、冲突结算、势力关系 |
| `fc-economy` | 税率、精确价格、配方效果 |
| `fc-colony` | 殖民地实验室岗位、维护、工程/造船工作单元 |

## 7. 验收与测试

必须覆盖：

1. 技能系数、工作进度与技能成长；
2. 船员上船、容量拒绝、随船移动与补给；
3. 航程风险三类结果、无负库存、可重放；
4. 价格 `BigDecimal` 精度与税率拆分；
5. 知识状态转换、勘察锁定、发现物持久化；
6. 科技前置、数据消耗、效果叠加与哈希；
7. 贸易协定税率、委托交付/到期、冲突损失与恢复；
8. D0–D4 判定与终局锁定；
9. “高效曲率线圈”完整因果链；
10. 全部既有测试 + 新测试通过，`verifyLedger()` 在每个结算点通过。

测试不得删除、跳过或放宽断言。实现过程中若发现设计与代码冲突，以本规格和新设计文档为准，先修规格/代码再继续。

## 8. 明确不在 M4

- 存档/读档、RNG 流持久化与版本迁移；
- Mod 加载、运行时编译、联机、JMX、PNG 导出；
- 程序化生成新地点；
- 玩家设施建造与改装 UI；
- 招聘新主体、人物关系网与生平；
- 家庭消费闭环；
- 战术战斗、舰船沉没与人员死亡；
- JDBC/XML/XSLT 编年史查询。

这些能力按设计稿属于后续批次，不能以 M4 名义提前引入。
