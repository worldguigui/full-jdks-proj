# M3 经济与殖民地

## 目标

让资源经过配方、运输与市场形成可核算的经济循环：玩家可以交易、升级前哨站、建立补给线，并通过殖民地维持人口；所有货物与资金变化都留下守恒证据。

## 货物与资金

- 11 种货物：燃料、能源、食物、水、矿物、金属、材料、设备、药品、奢侈品、科研数据。
- 信用点不属于货物，只能存在于 `MoneyLedger` 的账户中；配置或代码把 `credits` 写进库存必须失败。
- `ResourceLedger` 是唯一权威库存：地点视图 `Stock` 只是账本分区；所有增减都经过账本。
- 在途货物单独持有于账本的在途分区，交付前不计入任何地点库存，也不凭空消失。

### 账户

| 账户 | 用途 |
|---|---|
| `PLAYER` | 玩家可用资金与负债 |
| `HOUSEHOLDS` | 工资收款方（当前模型） |
| `BANK` | 贷款本金与利息的对手方 |
| `TREASURY` | 无具体势力归属时的公共账户 |
| 地点账户 | 每个静态地点的运营资金 |
| 势力账户 | 每个势力的财政 |

账户间转账必须等额；余额不足的转账被拒绝，不得透支。贷款把本金记入玩家余额并形成债务，利息按未偿还本金逐日计提并转移给银行。

## 配方生产

- 配方定义在地点，包含输入、输出与工时（ticks）。
- 开工条件：地点存在、未处于生产中断、配方未在运行、输入齐备、至少有一名在岗工人。
- 输入在开工时一次性扣除；缺料即不开工，不允许边生产边补料。
- 工作单元记录参与者、进度与总工时；每个工人每天只能投入一个工作单元。
- 已有工作单元的工人先被占用；剩余工人按配方 id 顺序轮转分配到可开工的配方，保证同一地点多个配方都有机会获得工人。
- 每名在场工人每 tick 推进 1 点进度；完工时按配方一次产出入库，并记录 `ProductionCompleted`。
- 自然产出只用于可再生原料（食物、水、矿物、能源）。设备、材料、药品、奢侈品与科研数据必须由配方生产。

## 定价与交易

单个地点的价格由其库存与配置的基准参数决定：

```
供需因子 = clamp((目标库存 / max(当前库存, 1)) ^ 弹性, 0.3, 5)
基准价 = 基准价配置 × 供需因子 × 事件冲击乘数
买入价 = 基准价 × 1.05
卖出价 = 基准价 × 0.95
```

- 库存低于目标 → 价格上升；库存高于目标 → 价格下降。
- 买卖价差构成交易成本；卖出价不低于 0.01。
- 事件冲击以乘数作用于基准价，持续若干天；冲击结束后价格回到纯供需定价。
- 交易在舰船货舱与地点库存之间转移货物，同时在地点账户与玩家账户之间转移资金。
- 库存或资金不足时按可成交数量部分成交；完全无法成交时返回失败且不改变状态。
- 成交后货物总量与资金总量都不变。

### 当前参数（暂定）

- 每日工资：每名在岗工人 1 信用点，由地点账户付给 `HOUSEHOLDS`；账户不足时欠薪并降低士气。
- 价格冲击：风暴对燃料、能源、材料施加 `1 + 0.05 × 强度` 的乘数，持续 3 天。
- 贷款日利率来自世界配置。

工资与家庭部门之间的回流规则尚未在设计层面确定，因此当前工资模型只作为局内运营成本，不宣称形成闭环宏观市场。

## 殖民地

### 等级与升级

- 前哨站为 0 级；殖民地等级 1–3。
- 只有玩家拥有的据点可以升级；升级必须满足目标等级的货物与信用点需求。
- 升级在地点扣除货物，并把信用点从玩家账户转入该地点账户；等级提升后写入 `ColonyUpgraded`。
- 升级配置必须满足：目标等级在 1–3、不重复、货物数量为正、信用点不为负。

### 人口与消费

- 1 级及以上殖民地每日消耗食物与水，数量为 `max(1, 人口 / 5)`。
- 物资不足时当地主体士气下降。
- 每 7 天尝试人口增长一次：需要 2 食物与 2 水，消耗各 1，人口上限 500。
- 0 级前哨站不参与人口消费与增长。

## 运输、转移与补给线

- `Transfer` 表示跨地点货物运输：出发时从来源分区转入在途分区，经过航线天数后进入目标分区。
- 取消运输把在途货物退回来源；任何时刻都不得复制或丢失货物。
- 补给线是周期性的单向调运：建立后的下一天首发，此后按间隔天数发车。
- 每次发车检查来源库存；不足则跳过该班次，不发空货、不产生负债。
- 取消补给线只停止后续发车；已经发车的运输继续完成。
- 补给线不是贸易合约，不进行买卖结算。

## 玩家目标

`goals` 面板展示当前进度。D0/D1 的正式判定阈值尚未在设计中确定；面板中的信用点、材料、设备、声望与补给线条件只是临时提示，不作为验收断言。

## 验收标准

| 项 | 标准 | 验证 |
|---|---|---|
| 定价 | 库存低更贵；买价高于卖价；极端库存被夹紧；冲击按乘数生效 | `EconomyTest#priceRisesWhenStockIsLow`、`#buyPriceAboveSellPrice`、`#priceIsClampedAtExtremes`、`#priceShockMultipliesPrice` |
| 交易守恒 | 买入/卖出后货物与资金总量不变 | `EconomyTest#tradeKeepsGoodsAndCreditsTotals`、`#sellReducesCargoAndAddsCredits` |
| 部分成交 | 库存不足时按实际库存成交；无钱拒绝 | `EconomyTest#buyIsPartiallyFilledWhenStockShort`、`#buyRejectedWhenPlayerCannotAfford` |
| 生产 | 扣输入、需工人、中断停产、完工产出一次 | `EconomyTest` 生产用例 |
| 工人独占 | 同一工人不同时进入两个工作单元 | `EconomyTest#eachWorkerIsAssignedToAtMostOneRecipe` 及多工人/在制单元用例 |
| 工资与利息 | 工资账户间转移；欠薪降士气；利息转移给银行 | `EconomyTest#wagesPaidFromLocationAccountToHouseholds`、`#unpaidWagesLowerMorale`、`#loanInterestIsPaidToBank` |
| 殖民地 | 升级权限/费用/等级；人口增长与物资约束 | `ColonyTest` |
| 运输与补给线 | 在途守恒、首班次日、按间隔、缺货跳过、取消后不再发车 | `ColonyTest` 补给线用例 |
| 账本一致 | 任意结算后 `verifyLedger` 通过 | `RuntimeSmokeTest#nextKeepsLedgersConsistent`、各经济用例 |

## 当前未覆盖

- 势力税率尚未进入交易结算；设计只说明“价格受税率影响”，未定义税基、纳税人与地点归属，暂不实现。
- 工资与家庭支出的闭环规则未定。
- 飞船类型、货舱容量与船体耐久/维修尚未建模。
- D1 的「知名」声望阈值与「贸易线」定义未定；当前补给线不计为贸易线。
- 贷款只有账本能力与利息计提，CLI 尚未提供借款/还款命令。
- 价格弹性目前通过 `double` 幂运算实现，尚未满足 BigDecimal 全链路要求；需要先确定定点幂算法与精度。
