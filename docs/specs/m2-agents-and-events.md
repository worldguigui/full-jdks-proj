# M2 主体与事件

## 目标

让世界在玩家不操作时也能演化：船员/居民/使者按统一规则感知、决策与行动；固定十二阶段 Tick 按确定顺序结算；事件形成可追溯的因果链；重大事件打断批推进。

## 主体

### 角色与状态

- 三种角色：`CREW`（船员）、`RESIDENT`（居民）、`ENVOY`（使者），共用同一个 `Agent` 类型。
- 每个主体有：位置、需求、性格、技能、指派、进食记录与可选的迁徙行程。
- 需求取值 0..100：饥饿与疲劳越高越糟，士气越高越好。
- 初始需求为饥饿 20、疲劳 10、士气 70。

### 需求阈值（当前生效参数）

| 判定 | 阈值 |
|---|---|
| 饥饿危急 | 饥饿 ≥ 75 |
| 疲劳过度 | 疲劳 ≥ 70 |
| 士气低落 | 士气 ≤ 20 |
| 日常进食 | 饥饿 ≥ 55（若当天尚未进食） |
| 日常进食缓解 | 饥饿 −25 |
| 危急进食缓解 | 饥饿 −45 |

这些数值是当前平衡参数，不是架构常量；调整时必须以测试确认行为仍然成立。

### 每日决策顺序

阶段 4（感知）与阶段 5（决策）对所有主体按 id 升序处理：

1. **迁徙中**：感知阶段推进一天行程；抵达后更新位置并产生 `CrewArrived`。当日不再做工作决策。
2. **生存**：饥饿危急且当日未进食 → 就地进食 1 单位口粮；无粮 → 沿无向航线寻找 6 天行程内最近的有粮地点并开始迁徙；找不到 → 产生一次 `CrewStarving` 告警（不重复刷屏），转为空闲。
3. **休息**：疲劳过度 → 休息。
4. **士气**：士气低落时按性格概率拒绝指令演出 `CrewRefusedDuty`，否则继续。
5. **工作**：默认回到工作；长期工作有低概率提升技能。

阶段 8（消耗）负责日常进食：饥饿达到阈值时消耗所在地点 1 单位口粮；缺粮时士气下降并可能产生饥饿告警。

迁徙以航线天数计，抵达前主体保留在原地点，不允许瞬移。

## 十二阶段 Tick

阶段顺序固定，不得因系统未实现而改变顺序。未启用的系统保留空阶段：

| # | 阶段 | 写入 |
|---|---|---|
| 1 | 时间 | 星历 +1、清理过期修正、采样天气 |
| 2 | 环境 | 地点自然产出、殖民地维护、人口变化 |
| 3 | 势力 | 势力采购与关系事件 |
| 4 | 感知 | 主体需求、迁徙抵达 |
| 5 | 决策 | 指派、进食、迁徙、拒绝 |
| 6 | 工作 | 配方开工、工作单元推进、完工产出 |
| 7 | 航行物流 | 舰船抵达、运输抵达、补给线发车 |
| 8 | 消耗 | 日常口粮、贷款利息 |
| 9 | 市场财务 | 工资、欠薪士气惩罚 |
| 10 | 事件 | 风暴传播、待决决策 |
| 11 | 编年史 | 将本 tick 事件按入队顺序落库 |
| 12 | 报告 | 聚合回合报告 |

## 确定性

- 同一种子 + 同一操作序列 → 同一状态哈希。
- 随机流按天气、事件、主体、市场、势力分别派生；某子系统多抽一次随机数不影响另一个子系统。
- 所有影响状态的遍历按 id 排序；工作单元按 key 排序推进。
- 工作阶段允许使用虚拟线程并行计算，但必须按 key 固定顺序汇合，结果与串行一致。

## 事件与编年史

- tick 内事件进入有序 `EventQueue`，阶段 11 统一写入编年史。
- 事件总线（`Flow`/`SubmissionPublisher`）只在 tick 结束后广播，供报告与遥测读取，**不得写入世界状态**。
- 玩家命令产生的即时事件（启航、交易、殖民地升级、补给线建立/取消）直接写入编年史；它们不参与 tick 队列。

### 离子风暴因果链

一次风暴至少产生以下可追溯序列：

1. `IonStorm`：记录发生地点与强度，必须先于影响事件入队；
2. `StormImpact`：沿无向航线逐跳传播，每个受影响地点一条，记录跳数与来源；
3. 状态后果：受影响地点生产中断 1–2 天、相邻航线风险上升、当地主体士气下降、途经该地点的在航舰船延误 1 天；
4. 价格冲击：燃料、能源、材料三种货物按强度写入限时涨价倍率，并各产生一条 `MarketPriceShocked`；
5. 强度 ≥ 4 且当前没有待决决策时，产生“风暴救援请求”待决决策（援助/拒绝），同时产生 `DecisionRaised`；
6. 阶段 11 按上述顺序落库；`trace` 命令可过滤查看风暴、决策与势力行动。价格冲击在阶段 1 的到期清理中撤销。

风暴参数（触发概率、强度、传播上限、援助代价）当前由代码固定，属于暂定值；配置化格式尚未定义。

## 势力

阶段 3 中每个势力按「日期 + 势力 id」错开采购节奏：当中心地点优先货物低于目标库存时，从最近富余地点采购并用 `Transfer` 运输。采购款在势力账户与来源地点账户之间转移，货物总量与资金总量都守恒。

势力关系矩阵与玩家声望已经进入状态；结盟、条约、宣战、委托等外交动作尚未实现。

## 待决决策

- 决策有 id、标题、描述、地点、关联势力、选项与后果类型；选项可以调整信用点、声望与士气。
- 声望后果只作用于决策关联的势力；没有关联势力时，声望参数被忽略，不记账到任何势力。
- 存在未解决决策时，`next` 不推进任何一天，CLI 给出提示。
- `decide <决策id> <选项id>` 应用后果并产生 `DecisionResolved`；之后时间才能继续。
- 一次 `next N` 可能因中途产生决策而提前结束。

## 验收标准

| 项 | 标准 | 验证 |
|---|---|---|
| 十二阶段 | 顺序固定且一次 tick 全部执行 | `M1TickTest#pipelineHasTwelveStagesInFixedOrder`、`M2SimTest#pipelineRunsTwelveStagesAndBroadcasts` |
| 随机流 | 同种子同序列；不同子系统互不干扰；不同种子不同 | `M2SimTest#rngSameSeedSameSequence`、`M2SimTest#rngSubsystemsAreIndependent`、`M2SimTest#rngDifferentSeedsDiffer` |
| 事件队列 | 入队顺序即落库顺序 | `M2SimTest#eventQueuePreservesOrder` |
| 进食 | 饥饿时消耗口粮并恢复 | `M2SimTest#starvingAgentEatsWhenFoodAvailable` |
| 迁徙 | 当天不瞬移；按航线天数抵达 | `M2SimTest#starvingAgentBeginsTravelWithoutTeleporting`、`M2SimTest#travelTakesLinkTicksAndArrives` |
| 告警 | 饥饿告警不重复 | `M2SimTest#starvingAlertIsNotRepeatedEveryTick` |
| 工作 | 按工人数推进；无工人不推进；完工移除 | `M2SimTest` 工作阶段用例 |
| 确定性 | 同种子同命令得到相同哈希 | `M2SimTest#sameSeedSameHistoryAndHash`、`RuntimeSmokeTest#sameSeedAndCommandsProduceSameHash` |
| 决策暂停 | 有待决决策时不推进；解决后恢复 | `M2SimTest#pendingDecisionPausesTimeUntilResolved` |

## 当前未覆盖

- 势力外交动作、条约与委托。
- 事件参数的配置化。
- 多技能模型（当前为单一整数技能，且不进入生产/航行公式）。
- 风暴对航程风险的实际事故判定（风险值已记录）。
