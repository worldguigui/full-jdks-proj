# 项目方向与设计原则（v4 修订）

> 修订日期：2026-11-20
> 状态：**已确立**，取代 v3（"API 覆盖优先，游戏作为承载载体"）。

---

## 一、项目定位（v4 升级）

项目定位由"单机星际经营游戏"正式升级为：

> **Full JDK 21 Project —— 基于 Java SE 21 的可扩展星际模拟与联机管理平台。**

以星际远征模拟游戏为**核心**，构建包含以下能力的综合应用：

- 数据管理（存档、加密、查询、导出）
- 规则扩展（Mod 编译、注解处理、动态装载）
- 动态编译与语言模型（`javax.tools` + `lang.model`）
- 运行时诊断（JMX、Instrumentation、agent）
- **远程通信与多人协作**（TCP/RMI/WebSocket/HTTP）
- 身份认证与授权（TLS、证书、SASL、Kerberos/GSS）
- 数字签名与数据交换（XML 签名、JDBC/RowSet）
- 桌面管理工具（Swing 客户端）

**核心游戏支持独立运行**；外围服务和扩展组件**按需启用**。优先使用 Java SE 21 正式标准 API，允许可选 Provider 和外部服务扩展。

这次升级的三个结果：

1. 原本被单机 CLI 产品边界排除的网络、安全、远程管理 API，现在有了真实应用场景；
2. 游戏不再是唯一的 API 使用载体，开发者工具和管理工具也是正式产品组成部分；
3. 项目有了从单机模拟到多人协作的自然演进路径。

---

## 二、项目目标（不变）

项目采用 **B：API 覆盖优先，游戏作为承载载体。**

> **以最大化 Java SE 21 正式标准 API 的功能性使用为首要目标，以「星际远征与自主世界模拟」游戏为核心载体，辅以联机通信、管理工具与开发者工具链。**

---

## 三、安全边界（v4 新增：本地可信 ≠ 远程可信）

本地可信原则继续保留，但**多人联机必须增加明确边界**：

| 对象 | 默认信任策略 |
|---|---|
| 本地玩家 | 充分权限 |
| 本地 Mod | 默认信任，允许深度扩展 |
| 本地管理工具 | 允许管理完整实例 |
| **远程普通玩家** | **只能访问授权的远程接口** |
| **远程管理员** | **通过明确授权获得管理能力** |
| **远程 Mod** | **不自动获得服务器本地权限** |

这不是把系统变成严格沙箱，而是避免"远程聊天室用户通过消息接口直接操作服务器文件或加载任意代码"。若管理员主动安装远程用户提交的 Mod，那是管理员的**主动信任决策**，不通过隐式网络接口获得权限。

## 四、设计原则

1. **API 能力优先探索**，不局限于原有游戏需求。
2. **允许 API_DRIVEN 功能成为一等功能类别**（与 CORE 同等准入资格）。
3. **优先构建完整 API 能力链**，而不是孤立调用单个类型。
4. **允许设备、Provider 和外部服务依赖**，但必须支持**可选运行和合理降级**。
5. **核心游戏不得依赖可选外部服务才能启动**（无网、无打印、无声卡时仍能正常游玩）。
6. **标准 API 与第三方实现严格区分**：覆盖统计只计算 Java SE 21 标准 API 类型。
7. **不允许虚假使用**，但**不能仅因功能超出传统游戏范围而排除 API**。
8. **每个类型必须能够追溯到功能、职责、实现和测试证据**。
9. **模块采纳 ≠ 功能锚点成立 ≠ 类型达到 L3**：这三者严格区分，12 个模块全部进入设计范围，但每个类型仍逐一论证。

---

## 五、第三方依赖约束

- **核心程序**不依赖第三方运行时或编译依赖。
- **允许经过明确设计的可选外部 Provider 和服务适配**（JDBC 驱动、脚本引擎、WebSocket 服务端、打印服务、音频设备），必须：SPI/接口适配、缺失降级、标注 `PROVIDER_REQUIRED` 且不计入覆盖。
