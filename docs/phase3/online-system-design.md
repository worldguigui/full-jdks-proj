# 星际远征通信与联机系统设计

> 项目定位升级为「Full JDK 21 Project：可扩展星际模拟与联机管理平台」后的联机子系统设计。
> 分三阶段：第一阶段聊天室（通信基础设施）→ 第二阶段远征协同 → 第三阶段多人世界（后续方向）。
> **本阶段只设计，不实现。**

---

## 一、总体定位

联机不是"聊天室"本身，而是一个**客户端—服务器通信系统**。聊天室是第一阶段可交付功能，用于建立并验证通信基础设施，之后在其上叠加协同与多人世界。

**三阶段路线**：

| 阶段 | 内容 | 是否本轮实现 |
|---|---|---|
| 一 | 聊天室（身份、频道、广播、私聊、成员列表、历史、存储、管理） | 设计，阶段五实现 |
| 二 | 远征协同（分享坐标/舰队状态/任务/报告、观战、远程状态） | 后续 |
| 三 | 多人世界（同星域经营、交易、联合探索、势力交互） | 后续，暂不做（世界状态所有权/并发/同步/断线恢复复杂） |

## 二、第一阶段：聊天室功能

1. 用户注册或创建临时身份；
2. 创建、加入、退出频道（`#general` `#exploration` `#trade`）；
3. 实时消息广播；
4. 私聊；
5. 在线成员列表；
6. 消息历史记录；
7. 服务器端消息存储；
8. 简单管理员管理。

这已构成真实的客户端—服务器系统，足以承载通信 API 能力链。

## 三、通信技术选型

> 关键判断：`java.net.http` 的 WebSocket API **只提供客户端能力**，不带通用服务端。因此分层：

| 通道 | 角色 | 说明 |
|---|---|---|
| **TCP Socket**（`java.net` + `java.nio.channels`） | 核心通信服务端 | 纯 Java SE 基础，聊天室核心承载 |
| **RMI**（`java.rmi`） | 远程方法调用 + 回调 | 频道/成员/消息的远程对象接口 |
| **WebSocket**（`java.net.http` 客户端） | 可选客户端接入 | 由可选服务端实现提供兼容端点，Java SE 客户端连接 |
| **TLS**（`javax.net.ssl`） | 加密通信链路 | 保护通信 |
| **SASL**（`javax.security.sasl`） | 可插拔协议认证 | 连接建立时的认证握手 |
| **Kerberos/GSS**（`java.security.jgss`） | 可选身份认证 | 企业级可选，非默认 |

**倾向**：先用 TCP Socket 或 RMI 建立核心联机能力，WebSocket 作为可选客户端接入方式；**不为覆盖 API 而让所有通信方式同时承担同一功能**。

## 四、安全边界（本地可信 ≠ 远程可信）

| 对象 | 默认信任 |
|---|---|
| 本地玩家 / Mod / 管理工具 | 充分权限（信任模型不变） |
| 远程普通玩家 | 仅授权远程接口（发消息、订阅频道、读成员列表） |
| 远程管理员 | 明确授权后获管理能力 |
| 远程 Mod | 不自动获服务器本地权限 |

实现要点：远程接口（RMI Remote / 消息协议）是**白名单边界**，只暴露授权操作；消息处理器不直接访问服务器文件系统或类加载器。

## 五、Java SE API 在联机系统中的应用映射

| API / 模块 | 职责 |
|---|---|
| `java.net` | Socket/ServerSocket 连接 |
| `java.net.http` | HTTP 客户端、WebSocket 客户端 |
| `java.rmi` | 远程对象调用、远程事件订阅 |
| `java.management.rmi` | 远程 JMX 管理 |
| `java.security.sasl` | 可插拔协议认证 |
| `java.security.jgss` | 可选 Kerberos/GSSAPI 认证 |
| `javax.net.ssl` | TLS 加密 |
| `java.security.cert` | 证书验证 |
| `java.xml.crypto` | 消息/Mod/数据包数字签名 |
| `java.sql` / `java.sql.rowset` | 玩家数据、聊天历史存储、离线结果集 |
| `java.naming` | 服务注册与命名（fc://） |

## 六、功能设计（十项要求）

**聊天室（CHAT，第一阶段）**：

1. **解决什么**：联机玩家需要实时通信频道，作为协同与多人世界的通信基座。
2. **服务谁**：玩家（PLAYER 锚点）。
3. **流程**：`> chat serve <port>` 起服务端 → 客户端 `> chat join <host>:<port> <identity>` → 加入频道 → 发消息/私聊 → 退频道。
4. **涉及类型**：`java.net`（Socket/ServerSocket）、`java.nio.channels`（Selector 多路复用）、`java.rmi`（远程对象）、`javax.security.sasl`（认证）、`javax.net.ssl`（TLS）、`java.sql`（历史存储）。
5. **类型职责**：见 type-keep.tsv 逐类型 api_role。
6. **Provider/外部依赖**：无（TCP/RMI 纯标准 API）；WebSocket 服务端可选第三方。
7. **核心启动**：聊天室是可选子系统，核心单机游戏不依赖。
8. **降级**：无网/不启动服务端时，聊天命令报"未启动"。
9. **验收**：双客户端连同一服务端，A 发消息 B 实时收到；历史消息可查；私聊只达目标。
10. **成本/风险**：中。并发连接管理、消息序列化、断线处理。

## 七、与"12 模块采纳"的关系

12 个模块全部进入功能设计范围，但：

- **模块采纳**（本设计）≠ **功能锚点成立**（feature-anchors.tsv 有 CHAT 等锚点）≠ **类型 L3**（type-keep 逐类型 api_role + L3）。
- 联机方向里，`java.rmi` / `java.net.http` / `java.security.sasl` / `java.security.jgss` 因联机场景从"排除"重开为候选，但仍需逐类型论证（见 expansion-v2 报告）。
