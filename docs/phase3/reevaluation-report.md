# 阶段三：现有映射重新评估报告

> 项目目标变更（API 覆盖优先）+ 准入体系重构（Planned 必须 L3 逐类型论证）后的重新评估结果。
> 分母保持阶段一冻结的 3836 类型 / 176 包 / 20 模块不变，所有变化来自逐类型状态调整。

---

## 一、状态重评：1684 / 128 / 2024 → 新分布

| 状态 | 重构前 | 重构后 | 变化 |
|---|---|---|---|
| Planned（L3 逐类型论证） | 1684 | **1544** | −140 |
| Pending（L1/L2 待论证） | 128 | **839** | +711 |
| Excluded | 2024 | **1453** | −571 |
| 合计（分母） | 3836 | 3836 | 不变 |

**变化的实质**：

1. **Planned −140**：上一轮 1684 个 Planned 里有 1336 个（79%）只是"模块级锚点"（MODULE_DEFAULT），即"属于某核心模块但未逐类型论证"。新体系下这些**不能直接 Planned**，须逐类型论证。本轮我为游戏主体的核心类型（语言基础、集合、IO、时间、并发、存档、配置、XML、图像、音频播放链路、JMX 观测等）补了 L3 论证，保留了 1544 个；其余 140 个（主要是有明确 API 角色的 JMX 外围子包、图像 renderable 等）降为 L2 候选。

2. **Pending +711**：14 个 API 机会方向（RMI/JNDI/TLS/证书/XML 签名/JDBC/规则编译/注解处理/Instrumentation/JMX 外围/打印/剪贴板等）从「Excluded」**重开为 L2 候选**，释放 753 个类型进入 Pending。它们功能已设计（有 feature 锚点 + 验收标准），但尚未逐类型论证 api_role，故停在 L2。

3. **Excluded −571**：被释放的 API 方向 + 上一轮误判的部分，从 Excluded 转 Pending；但 Swing GUI 组件（788）、AWT GUI（事件/拖放/桌面/输入法）、废弃 API（54）仍保持 Excluded——这些是纯 CLI 载体下确实无场景、或已废弃，**不是"为覆盖而排除"**。

## 二、四级覆盖率变化

| 指标 | 重构前（包级口径） | 重构后（逐类型口径） | 潜在上限（Pending 全升 L3） |
|---|---|---|---|
| 类型级 | 43.90% | **40.25%**（1544/3836） | **62.12%** |
| 包级 | 48.86% | **45.45%**（80/176） | 更高 |
| 完整包 | 39.20% | **35.80%**（63/176） | 更高 |
| 模块级 | 35.00% | **30.00%**（6/20） | 更高 |

**关键解读**：

- 类型级 40.25% 是**当前已逐类型论证（L3）**的规划覆盖；62.12% 是**若全部 L2 候选在阶段四通过论证**的理论上限。
- 模块级 30%（6/20）看似暴跌，实际是因为旧口径把"包内只要 1 个 Planned 就算模块覆盖"，新口径下模块覆盖同样要求逐类型论证。6 个模块（java.base、java.xml、java.compiler、java.desktop、java.logging、java.prefs）是真正有 L3 论证的模块。
- 这组数字**更诚实**：它区分了「论证过」和「计划中」，而不是用一个虚高的包级数字掩盖"包级规则批量继承"的问题。

## 三、按功能来源（feature_origin）的分布

| 来源 | Planned | Pending | 说明 |
|---|---|---|---|
| CORE | 805 | 2 | 游戏核心，绝大部分已 L3 论证 |
| INFRASTRUCTURE | 365 | 0 | 存档/配置/日志/偏好，已 L3 论证 |
| API_DRIVEN | 308 | 719 | 已论证 308（音频/JMX 观测/图像/模组/撤销），候选 719（远程/证书/签名/JDBC/打印/剪贴板等） |
| DEVELOPER_TOOLING | 66 | 118 | 已论证 66（测试/装配），候选 118（注解处理/agent） |

**这组数据印证了目标变更的意义**：API_DRIVEN 功能从"被排除"变为"最大的 Pending 候选池（719 类型）"，正是「API 覆盖优先」下的待论证空间。

## 四、论证层级分布（非 Excluded 类型）

| 层级 | 数量 | 状态 |
|---|---|---|
| L3（逐类型论证） | 1544 | Planned |
| L2（功能级，待逐类型） | 839 | Pending |
| L1（包级） | 0 | 已全部升级为 L2 或排除 |

**L1 清零**是本次重构的标志性结果：不再有任何"包级理由直接 Planned"的类型。

## 五、排除原因分布

| 原因码 | 数量 | 说明 |
|---|---|---|
| BIZ | 1399 | 业务无关（Swing GUI、AWT GUI、废弃、无场景的 SPI） |
| DEPRECATED | 54 | 废弃 API（SecurityManager 体系、RMI 桩、SAX1、Observable） |
| ENV | 0 | 已清零：脚本引擎、剪贴板从 ENV 排除转为 API_DRIVEN L2 候选 |
| ACCESS | 0 | protected 嵌套（不在分母内，另见 phase1 扩展清单） |

**ENV 清零的含义**：上一轮把「脚本引擎无内置引擎」「剪贴板无头不可用」标为 ENV 排除；新目标下它们转为「API_DRIVEN 候选（L2）」，通过可选 Provider / 降级策略处理，而非排除。这正符合"允许设备、Provider 依赖，但支持可选运行和降级"的原则。

## 六、仍存在的设计决策与技术风险

### 6.1 需裁决的设计决策

| # | 决策 | 现状 | 影响 |
|---|---|---|---|
| 1 | JDBC 驱动策略 | 自研只读驱动 vs 第三方嵌入式库 vs 放弃改 XPath | 104 类型 Pending，唯一破坏"核心零第三方"的候选 |
| 2 | 规则编译安全边界 | `javax.tools` 动态编译的沙箱（禁反射/IO/网络） | 24 类型 Pending |
| 3 | JNDI LDAP 子包 | 无目录服务器，LDAP 22+2 建议 BIZ 排除 | 24 类型 |
| 4 | JMX 外围时间模型 | monitor/timer 独立时间源 vs 单一 Stardate | 约 50 类型 |
| 5 | Swing 非 GUI 模型 | table/tree 是否保留（上轮已否决，维持） | 34 类型 |

### 6.2 技术风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 839 个 L2 候选积压 | 阶段四逐类型论证工作量巨大 | 按 priority（P1 先行）分批论证，M5 后置 |
| 自研 JDBC 驱动工作量失控 | 阶段五排期 | 限定 SQL 子集（SELECT/WHERE/ORDER/LIMIT） |
| 动态编译安全 | 规则注入攻击 | 白名单 + 禁反射/IO + 独立类加载器 |
| 反序列化漏洞 | 远程观战安全 | ObjectInputFilter 白名单 |
| 设备降级覆盖不全 | 音频/打印/剪贴板证据不足 | 以"降级行为"为验收标准 |

## 七、结论

1. **准入体系已重构完成**：Planned 必须 L3 逐类型论证，L0/L1 不产出 Planned，L2 产出 Pending，L4 可 Verified。生成器 12 条硬校验全部通过。

2. **API 机会已盘点**：14 个方向（`api-opportunity-report.md`）逐一给出九项分析，其中 RMI/JNDI/TLS/证书/XML 签名/JDBC/规则编译/注解处理/Instrumentation/打印/剪贴板 11 个方向建议纳入（L2 候选），Swing GUI 除 undo 外建议排除，AWT 仅无头绘图纳入。

3. **重新评估完成**：Planned 1544（40.25%，当前已论证）/ Pending 839（L2 候选，潜在上限 62.12%）/ Excluded 1453。分母未动。

4. **下一步（阶段四）**：对 839 个 L2 候选逐类型论证 api_role + justification，升 L3 后转 Planned。**本阶段不启动 M0，不进入游戏实现。**

5. **待人工审阅**：§6.1 的五项设计决策 + 本报告的重新评估结果。
