## 一、本轮审查修订内容

本轮针对复审发现的架构、排期、统计与可验证性问题，修改了 `game-design.md` 并补齐工程约束；**未改动阶段一冻结数据与审计证据**。

### 1. P0：架构硬伤

| # | 问题 | 修订 |
|---|---|---|
| 1 | **sealed 与原 14 模块划分冲突**：JLS §8.1.6 要求命名模块内 permitted 子类与 sealed 根同模块，原设计却让领域模块各自扩展 | 全部 sealed 根与 permitted 类型收敛到 `fc-world`；领域模块只提供行为；新增 `non-sealed` 的 `ExtensionLocation` / `ExtensionEvent` 作为 mod 扩展口（现为 15 模块，新增 `fc-config`） |
| 2 | `World` ↔ `TickPipeline` ↔ `Chronicle` 循环依赖；配置由 `fc-persist` 在 M5 提供，启动期倒置 | 拆分 `WorldState`（纯数据根，`fc-world`）与 `GameLoop`/`TickPipeline`（`fc-sim`）；`Chronicle` 接口在 world、实现在 `fc-history`；新增 `fc-config`（world 之上、sim 之下），共 **15 模块** |
| 3 | `Ship` 未进入 `Location` 层级，「船员在船上 / 货物在船上」无统一位置模型 | `Ship` 作为移动 `Location`（`parent()` / `cargo()` / `voyage()`）；`Colony` 为图节点，`Facility` 归属殖民地子图 |

### 2. P1：正确性与可验证性

| # | 问题 | 修订 |
|---|---|---|
| 4 | 配置装载排到 M5，M1–M4 必然硬编码 | `fc-config` 随 M0 落地，M1 起世界数据全部配置驱动；M5 只保留本地化、存档迁移、mod 配置合并 |
| 5 | 覆盖率目标与逐包核算不符（原「≥85%、15–20 包排除」） | 实际约 **31 包 / 1089 类型**需排除；包级上限 `145/176 = 82.4%`，类型级上限 ≈72%；目标改为包级 ≥80%、类型级 65–72%、模块级 ≥90% |
| 6 | 注解处理器无法证明方法体内真实使用 | 审计改为**源码/classfile 扫描为主**、注解处理器仅作补充标记；M6 接入 |
| 7 | `Flow` 默认异步分发破坏同种子重放 | Tick 内使用确定性同步有序队列；`Flow` 仅在 tick 结束后向报告/遥测投递 |
| 8 | RNG 只存种子，读档后流位置错位 | 存档写入 RNG 算法/种子/流位置（或种子 + 操作日志重放）；新增 save→load→N tick 哈希一致性测试 |
| 9 | 标准 `Console` 不支持按键级读取，Tab 补全不可移植 | Tab 补全改为尽力而为：可探测 TTY 时启用，否则退化为行尾建议 + `?` 候选列表 |
| 10 | 无冲突/威胁结算；`WorkUnit` 仅单驱动；credits 与库存重复记账 | 补最小冲突/威胁事件链与重放测试；`WorkUnit` 支持多 Agent 协作；**11 种货物 + credits**，credits 仅存权威 `ResourceLedger`，`Stock` 是分区视图 |
| 11 | 冻结清单 SHA-256 在 Windows 工作区不匹配（CRLF） | 诊断为 `core.autocrlf=true` 且无 `.gitattributes`；新增 `.gitattributes`（`*.csv`/`*.md`/`*.java`/`*.sh` 均 `eol=lf`），并在冻结说明中注明哈希基于 LF 内容 |

### 3. P2：术语与口径一致性

- `Module` → `ShipModule`，`ResourceBundle` → `ResourceLot`，避免与 `java.lang.Module` / `java.util.ResourceBundle` 混淆（本地化仍用 `java.util.ResourceBundle`）。
- `Crew` / `Resident` / `Envoy` 统一为 `Agent` 的 `AgentRole` 角色，不再定义为并列类。
- 「四类扩展清单」更正为**三类**：`extension-smartcardio.csv` 13 / `extension-preview.csv` 38 / `extension-protected-nested.csv` 168。
- 明确 `Excluded` 只改映射状态、**不改覆盖率分母**（分母 3836 类型 / 176 包 / 20 模块）。
- 新增 §20「v3 审查修订摘要」，便于逐条核对。

## 二、阶段二设计要点（确认版）

- **16 个系统**（§4.1–§4.16）与 **9 个重点问题**逐一回应；**11 项交付内容**齐全；附任务书对照索引。
- **统一世界规则**：`Location` / `Link` / `Agent` / `Stock`+`ResourceLedger` / `WorkUnit` 五抽象 + 单一 `Stardate` + 单一 `Chronicle`；尺度差异由子类型与配置参数表达。
- **核心循环**（§5）落地任务书 §2.3 七步；**12 阶段 Tick**（§8.2）按依赖 DAG 排序；**双终局**（归途 / 扎根）+ D0–D4 发展阶段。
- **初始规模**：1 星域 / 16 地点 / 4 势力 / 3→8 船 / 36 船员 / 1 殖民地 / 12 类资源（11 货物 + credits）。
- **CLI 可玩性**：信息三层下钻、叙事化回合报告、按游戏动作组织的命令体系、ASCII 星图与可选 PNG。
- **阶段边界**：§15 只给域级 API 覆盖策略与风险预判，**未做逐类型映射**（属阶段三）。

## 三、关键决策及理由

| # | 决策 | 理由 |
|---|---|---|
| 1 | 统一世界规则（五抽象 + 一时间轴） | 任务书硬性要求；从类型系统层面杜绝「两个子游戏拼接」 |
| 2 | `Ship` 作为移动 `Location`；`Colony` 节点 / `Facility` 子图 | 船员、货舱、在途状态复用同一位置与账本规则，避免舰队变成第二套模拟器 |
| 3 | sealed 模型全部收敛 `fc-world`，扩展用 `non-sealed` | 符合 JPMS 同名模块约束；领域模块只提供行为，依赖方向单向无环 |
| 4 | 独立 `fc-config`，M0/M1 即可用 | 世界数据从第一天起配置驱动，避免后期硬编码返工 |
| 5 | Tick 内同步有序队列，`Flow` 仅 tick 后投递 | 结算与重放必须确定；异步分发会破坏同种子哈希 |
| 6 | 存档写入 RNG 流状态 | 只存主种子无法复现已消耗序列，读档行为会漂移 |
| 7 | 审计以源码/classfile 扫描为主 | 注解处理器只能看到注解点，无法证明方法体真实使用 |
| 8 | 覆盖率目标按逐包核算：包级 ≥80%、类型级 65–72%、模块级 ≥90% | 31 包 / 1089 类型不可用，包级上限 82.4%、类型级上限 ≈72%；目标可达且诚实 |
| 9 | 旧设计稿整体作废、不修补 | 新任务书世界观、系统清单、循环与重点问题均不同，重写一致性更好 |

## 六、与 API 覆盖目标相关的风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `java.desktop` GUI 主体（18 个 Swing 包 / 797 类型） | 包级上限 82.4%、类型级上限 ≈72% | 逐包核算、如实记录 `Excluded` + 理由；不粉饰、不改分母 |
| 38 个 Preview 类型全部禁用 | 现代并发/FFM 覆盖缺失 | 用正式 API 等价实现；单独登记，不入分母 |
| 无头/外设差异 | 个别类型环境依赖 | 能力探测 + 优雅降级；原因码 = 环境限制 |
| **sealed 与 JPMS 模块冲突** | 编译失败或模型被迫拆散 | sealed 全部收敛 `fc-world`；构建期模块边界校验；扩展只用 `non-sealed` |
| **配置装载排期过晚** | M1–M4 硬编码返工 | `fc-config` 随 M0 落地；M1 起数据驱动 |
| **`Flow` 异步分发** | 同种子重放哈希漂移 | Tick 内同步有序队列；`Flow` 仅 tick 后投递 |
| **RNG 状态未入档** | 读档随机序列错位 | 存档写入算法/种子/流位置；§16-10 往返测试 |
| **审计证据不足** | 阶段五无法证明真实使用 | 源码/classfile 扫描为主 + 场景证据 |
| 自研 JDBC / ScriptEngine / JNDI / 运行时编译 | M5 延期 | 只读/最小语义；砍范围不砍合理性 |
| 虚拟线程 + 共享账本并发 | 死锁/竞态/确定性破坏 | 固定顺序汇合、领域锁规约、有序集合、压测入 CI |
| 覆盖率诱惑（塞无意义调用） | 违反任务书 §5 | 阶段五静态审计 + 人工复核；宁可低分不造假 |
